## 2026-08-17 - RouteMetrics.from_path Optimization
**Learning:** In hot loops analyzing path metrics in network graphs, looking up dictionary values (e.g. `utilization`) on every edge hop when they are only needed when a bottleneck candidate (min bandwidth) changes creates unnecessary dict lookup overhead. Pre-allocating `float("inf")` outside loops and removing redundant `float()` conversions on already-typed numerical attributes significantly reduces loop overhead.
**Action:** Avoid querying dict attributes in graph traversal loops unless the conditional requirement for those attributes is met.

## 2026-08-23 - BaseRouter.validate_path & SimulationEngine Hot Path Optimization
**Learning:** Calling `@property` accessors like `topology.nodes` or `topology.edges` constructs new Python `list` allocations of all node strings or edge tuples on every call. In path validation loops executed for every computed path (thousands per simulation), `(u, v) not in topology.edges` causes O(E) linear list scans resulting in tens of millions of string tuple comparisons. Directly querying NetworkX graph methods (`node in topology.graph` and `topology.graph.has_edge(u, v)`) and set membership (`topology._down_nodes`, `topology._down_edges`) reduces validation overhead from O(E * path_len) to O(path_len), yielding up to a 16x speedup in Dijkstra/RL routing path calculations and a 3.66x overall simulation speedup.
**Action:** Always prefer direct O(1) NetworkX graph lookups (`node in graph`, `graph.has_edge(u, v)`) over property lists (`topology.nodes`/`topology.edges`) in hot graph traversal and validation loops.
